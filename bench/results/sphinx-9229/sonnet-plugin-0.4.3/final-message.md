Docstrings on type aliases that point to a class are now shown instead of just "alias of …". The new regression test fails without the fix and passes with it. The autodoc test files I ran (`test_ext_autodoc.py`, `test_ext_autodoc_autoclass.py`, `test_ext_autodoc_autodata.py`) pass, 93 in all. I did not run the full test suite.

**Cause.** When a class is documented under a different name (`Alias = SomeClass`), `ClassDocumenter` treats it as an alias and discards its docstring. It also replaces the content with "alias of …". The doc comment on the alias was never found, because the lookup used the module that defines the class, not the module that defines the alias. On the reporter's Python 3.6, typing generics such as `Dict[...]`, `Union[...]` and `Callable[...]` are real classes, so they hit this path. That probably explains the inconsistency, though I only reproduced the class-alias case.

**What I did not reproduce.** On the 3.9 environment here, those typing aliases take a different path, which already keeps the docstring. I couldn't run the reporter's exact `file.py` on 3.6, because the guard blocked writing a scratch module. I used a separate fixture where the alias and the class live in different modules.

**Fix.** In `sphinx/ext/autodoc/__init__.py`, `ClassDocumenter` now has a `get_variable_comment()` that looks up the alias's doc comment in the module the alias is documented in. `get_doc` returns that comment for an alias, and `add_content` only adds "alias of …" when there's no comment. Aliases without a comment still show "alias of …", so existing tests are unchanged.

**Test.** I added `test_class_alias_having_doccomment` in `tests/test_ext_autodoc_autoclass.py`, with the fixture `tests/roots/test-ext-autodoc/target/classalias.py`. It covers a `#:` comment and a `"""` docstring below the assignment. A third alias with no comment is in the fixture but not in the expected output, because members without docs aren't listed by default.
