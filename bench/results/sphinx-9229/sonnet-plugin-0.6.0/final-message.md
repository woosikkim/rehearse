I fixed the cause I could reproduce. A `"""` docstring under an alias of a class from another module is now rendered, instead of only `alias of ...`. I couldn't reproduce your exact pyscaffold example on this setup (Python 3.9). The fix covers the same mechanism you'd hit on Python 3.6, which I haven't run.

- **Why your example works here:** On Python 3.9, `Dict[str, Any]`, `Union[...]` and `Callable[...]` take autodoc's generic-alias path, and all three of your docstrings rendered correctly.
- **The bug I reproduced:** `Alias = collections.OrderedDict` followed by `"""Alias doc."""` showed only `alias of "collections.OrderedDict"`. Autodoc looks up the alias's doc-comment in the aliased class's module (`collections`) instead of the module where the alias is assigned.
- **Likely cause for you:** I expect your case is the same thing. On Python 3.6, `typing.Dict[str, Any]` is a class defined in `typing`. That would explain why only some of your aliases lost their docs. I inferred this and didn't test it.
- **The change:** It's in `ClassDocumenter` in `sphinx/ext/autodoc/__init__.py`. A new `get_variable_comment()` looks the comment up in the module where the alias is assigned. `add_content()` now adds that comment when the analyzer missed it, and keeps the `alias of ...` line below it, as the same-module case already did.
